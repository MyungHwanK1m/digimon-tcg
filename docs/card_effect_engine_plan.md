# 🧩 카드 효과 확장 계획 — "수천 장의 카드가 실제로 동작하는 대전 엔진"

> 목표: 카드를 한 장씩 손으로 코딩하지 않고, **카드 데이터만 늘리면 효과가 동작하는 구조**로 바꾼다.
> 대상: 현재 도감 4,497장 (효과 구현 120장 · 나머지는 DP · 코스트 · 기본 키워드만 적용)

---

## 1. 현재 구조와 한계

| 영역 | 지금 | 문제 |
| :--- | :--- | :--- |
| 카드 데이터 | 내장 120장이 `StarterDecks.cs`에 C# 코드로 하드코딩, 나머지는 `cards_cache.json`(API 원본) | 카드 추가 · 수정 = 코드 수정 + 빌드. 내장 120장 중 약 40장은 번호와 실제 카드가 다름 |
| 효과 처리 | `GoldfishEngine`에 `if (CardId == "ST1-16")` 식 분기 약 25개 | 카드가 늘수록 분기가 끝없이 늘어남. 효과 문장과 실제 동작이 따로 놀음 |
| 플레이어 / AI | 플레이어는 `PlayCard`, `EvolveDigimon` 등, AI는 `ExecuteStage3AiTurn` 안의 별도 간소화 로직 | 같은 카드가 플레이어 · AI 쪽에서 다르게 동작. 효과를 두 번 구현해야 함 |
| DP · 버프 | `TamerDpBonus`, `TemporaryDpBonus`, `InheritedDpBonus` 같은 고정 필드 | 조건부 · 지속 효과("[자신의 턴] 진화원 4장 이상이면 +1000")를 표현할 수 없음 |
| 대상 선택 | 엔진이 임의로 첫 번째 / 최고 DP 대상을 고름 | "상대 디지몬 1체를 고른다" 같은 효과를 제대로 할 수 없음 |
| 한글 | 120장 수동 번역 | 4,000장 이상은 번역 불가능한 규모 |

## 2. 효과 문장 빈도 분석 (영어 효과가 있는 4,256장 기준)

**발동 시점** — [진화 시] 34.8% · [등장 시] 33.2% · [한 턴에 한 번] 33.7% · [자신의 턴] 26.1% · [시큐리티] 22.3% · [모든 턴] 21.2% · [공격 시] 19.7% · [메인] 16.4% · [소멸 시] 11.3%

**동작** — 트래시 34.0% · 소멸 19.1% · 메모리 +N 14.3% · DP +N 12.3% · 레스트 10.7% · 액티브 10.3% · 덱 위 N장 공개 9.9% · DP −N 6.1% · 패로 되돌리기 4.4%

**키워드** — ＜블로커＞ 11.9% · ＜드로우＞ 11.8% · ＜시큐리티 어택＞ 9.3% · ＜관통＞ 4.3% · ＜디지몬 퇴화＞ 4.1% · ＜재가동＞ 3.3% · ＜재밍＞ · ＜리커버리＞ · ＜속공＞ · ＜보복＞ · ＜습격＞ · ＜동맹＞ 각 2~3%

**특수 메커닉** (DNA 진화 · 디지크로스 · 앱 합체 · 링크 · ACE 오버플로 · 디지버스트) — 8.4%

→ 발동 시점 10종 + 동작 20종 정도 + 키워드 15종이면 **대부분의 효과 문장이 조합으로 표현된다.** 특수 메커닉은 후순위로 둔다.

## 3. 목표 구조

```
 [DigimonCard.io API] ──동기화──▶ cards_cache.json (영어 원본, 자동 갱신)
                                        │
 card_overrides.json (사람 관리) ───────┤  한글 이름 · 수동 수정 · 에라타
 effects/*.json      (사람/파서 생성) ──┤  카드별 효과 스크립트
                                        ▼
                         ┌──── 카드 효과 로더 ────┐
                         │ ① 수동 스크립트 (JSON)  │  우선순위 ① > ② > ③
                         │ ② 문장 템플릿 파서      │
                         │ ③ 키워드 사전           │
                         └──────────┬─────────────┘
                                    ▼  구조화된 Effect 목록 + 절별 지원 상태
                 ┌──────────── 규칙 엔진 (이벤트 기반) ────────────┐
                 │ 이벤트 버스 · 효과 대기열 · 지속 효과 레이어      │
                 │ 공용 행동 API (등장 / 진화 / 공격 / 시큐리티 …)   │
                 └───────┬───────────────────────────┬─────────────┘
                 플레이어 (UI 대상 선택)          AI (선택 정책만)
```

### 3-1. 데이터 분리
- `StarterDecks.cs`의 하드코딩 카드 정의를 없애고, 모든 카드를 `cards_cache.json`(API 원본) 하나에서 읽는다.
- 사람이 관리하는 정보는 `card_overrides.json`에 둔다: 한글 이름, 수동 수정값, 에라타.
- 추천 덱(프리셋)도 `decks/*.json`의 카드 번호 목록으로 옮긴다.
- 카드를 추가 · 수정할 때 빌드가 필요 없다.

### 3-2. 효과 모델 (Effect)
카드의 효과 한 절 = 아래 요소의 조합.

| 요소 | 예 |
| :--- | :--- |
| **출처** | 메인 효과 / 진화원 효과 / 시큐리티 효과 |
| **발동 시점** | 등장 시 · 진화 시 · 공격 시 · 소멸 시 · 자신의 턴 시작 / 종료 · 메인 · 시큐리티 · 상시(자신의 턴 / 상대 턴 / 모든 턴) |
| **조건** | "테이머가 있으면", "진화원 N장 이상", "메모리 N 이하", "상대 시큐리티 N장 이하" |
| **대상** | 소유자(자신 / 상대) · 위치(배틀 / 패 / 트래시 / 시큐리티) · 필터(Lv ≤ N, DP ≤ N, 색, 종류, 특징, 이름) · 수(1체 / 전부 / 최대 N) · 고르는 쪽 |
| **동작** | 드로우 · 메모리 ± · DP ± (기간) · 소멸 · 레스트 / 액티브 · 패 / 덱 아래로 · 시큐리티 트래시 / 추가(리커버리) · 퇴화 · 덱 위 N장 공개 후 추가 · 무료 등장 · 키워드 부여 |
| **제약** | 한 턴에 한 번 · "~할 수 있다"(선택) · 비용(레스트 등) |

예) `[When Digivolving] Delete 1 of your opponent's Digimon with 4000 DP or less.`
→ `{ 발동: 진화 시, 대상: 상대 · 배틀 · DP ≤ 4000 · 1체 · 자신이 선택, 동작: 소멸 }`

### 3-3. 효과 인식 파이프라인
1. **키워드 사전** — ＜블로커＞, ＜관통＞ 등 키워드는 규칙이 정해져 있으므로 이름만으로 동작을 붙인다.
2. **문장 템플릿 파서** — 영어 효과 문장을 정규식 / 문법 규칙으로 Effect 로 바꾼다. 빈도가 높은 문장 틀부터 추가한다. 해석하지 못한 절은 '미지원'으로 남긴다(조용히 무시하지 않는다).
3. **수동 스크립트(JSON)** — 파서가 못 읽는 카드는 `effects/{카드번호}.json`에 직접 적는다. 코드 수정 없이 데이터로 추가.
4. **C# 훅** — 정말 특수한 극소수 카드만.

카드마다 **절 단위 지원 상태**(✅ 동작 / 🟡 부분 / ⛔ 미지원)를 계산해 UI · 덱 빌더 · 리포트에 쓴다.

### 3-4. 규칙 엔진 (이벤트 기반)
- **공용 행동 API** — 등장 · 진화 · 공격 · 시큐리티 체크 · 소멸 · 턴 진행을 하나의 경로로. 플레이어와 AI가 같은 함수를 쓴다(지금의 `ExecuteStage3AiTurn` 별도 로직 폐기). AI는 "무엇을 할지"만 고르는 정책 계층이 된다.
- **이벤트 버스** — `CardPlayed`, `Digivolved`, `AttackDeclared`, `SecurityChecked`, `Deleted`, `TurnStarted`, `TurnEnded` 등을 발행하고, 해당 시점의 효과를 대기열에 올린다.
- **효과 대기열** — 공식 룰 순서(턴 플레이어 먼저, 동시에 발동한 효과의 처리 순서)대로 처리.
- **지속 효과 레이어** — DP · 키워드 · 시큐리티 어택 수치를 고정 필드 대신 "현재 유효한 효과들"로부터 계산한다. 조건부 효과가 자연스럽게 표현된다.
- **선택 인터페이스(`IChoiceProvider`)** — 대상 고르기 · "~할 수 있다" 여부를 묻는다. 플레이어는 UI 팝업으로, AI는 평가 함수로 답한다.
- 상대 턴 리플레이(`OpponentTurnEvents`)는 이벤트 버스에서 자동으로 만들어진다.

### 3-5. 한글화 — 번역하지 않고 "생성"한다
- 파싱된 Effect 를 한글 문장 틀로 렌더링한다. 예) `{진화 시, 상대 DP ≤ 4000 1체 소멸}` → "[진화 시] 상대의 DP 4000 이하 디지몬 1체를 소멸시킨다."
- 용어는 한 곳(용어집)에서 관리 → 4,000장 이상 표기가 자동으로 통일된다.
- 카드 설명에는 **한글(생성) + 영어 원문**을 함께 보여 준다. 해석하지 못한 절은 원문만 표시하고 ⛔ 표시.
- 공식 한국어판 표기를 확인할 수 있으면 용어집과 이름을 거기에 맞춘다.

### 3-6. 품질 관리
- 동작(액션) 단위 테스트, 파서 골든 테스트(영어 문장 → 기대 Effect), 인기 카드 시나리오 테스트.
- **지원률 리포트**: 세트별 · 전체 카드 기준 ✅ / 🟡 / ⛔ 비율을 앱(덱 빌더)과 테스트 출력으로 보여 준다. 단계마다 이 숫자로 진척을 잰다.

- 각 단계가 끝날 때마다 앱이 정상 동작하는 상태를 유지한다(중간에 게임이 깨지지 않게).

## 5. 정해야 할 것

1. **지원 범위** — 특수 메커닉(8.4%)을 언제 다룰지. 제안: 7단계까지 미루고, 해당 카드는 덱 빌더에서 '⛔ 미지원 메커닉'으로 표시.
2. **미지원 카드 정책** — 덱에 넣는 것을 막을지, 경고만 할지. 제안: 경고만(지금처럼), 대신 덱 지원률을 표시.
3. **한글 표기 기준** — 공식 한국어판 표기를 따를지, 자체 용어집으로 갈지. 제안: 공식 표기를 찾을 수 있으면 공식, 아니면 자체 용어집.

## 7. 0단계 결과 (현재 상태)

- **카드 데이터**: `StarterDecks.GetAllCatalogCards()` 120장을 생성 스크립트로 다시 만들었다. 이름 · 효과 문구는 공식 한글판 카드 이미지, 레벨 · 코스트 · DP · 진화 조건 · 등급은 DigimonCard.io 값. 오메가몬 3종의 2색 진화 조건은 카드 이미지로 확인(BT1-084 · BT5-086 레드/블루, BT3-112 레드/블랙).
- **효과 코드**: `GoldfishEngine.Effects.cs` (partial class)에 모았다. 기존 ID 분기 중 실제 카드와 달랐던 것(신태일 "최소 메모리 3", 슬래쉬엔젤몬 소멸, 해머 스파크 +2 등)은 실제 효과로 교체.

  - 기간 효과: `GameState.TurnSequence`(플레이어 · 상대 턴마다 +1) 기준 "다음 상대의 턴 종료 시까지" 등

## 9. 2단계 결과 (키워드)

### 키워드 사전 — `Engine/Effects/KeywordDictionary.cs`
API로 받은 카드(영어 문장)에서 두 가지 절을 인식해 카드 스크립트를 자동으로 만든다 (`CardScripts.For(card)` — 내장 카드는 사람이 쓴 스크립트, 그 밖은 자동 스크립트).
- **키워드만 있는 절**: `＜Blocker＞ (설명)`, `＜Rush＞ ＜Piercing＞` … → 상시 키워드 (메인 / 진화원 칸 구분). 설명문 안의 키워드(예: ≪연계≫ 설명의 ＜Security A. +1＞)는 건너뛴다.
- **발동 시점 + 동작 키워드 하나로 된 절**: `[On Play] ＜Draw 1＞`, `[When Digivolving] ＜De-Digivolve 1＞ 1 of your opponent's Digimon.`, `[Main] ＜Recovery +1 (Deck)＞`, `[When Digivolving] ＜Blitz＞` …
  - 시점: 등장 시 · 진화 시 · 어택 시 · 소멸 시 · 메인 · 시큐리티 · 자신의 턴 개시 시 · 어택 종료 시, `[Once Per Turn]` 수식
  - 대상: `N of / all of your opponent's Digimon`
  - "Then, ~"처럼 문장이 이어지거나 조건이 붙은 절("While ~, it gains ＜Piercing＞")은 문장 파서(3단계) 대상으로 남긴다.
- ≪블로커≫ · ≪시큐리티 어택 ±N≫ 수치(`CardData.IsBlocker` 등)도 같은 사전으로 계산한다 — 문장 맨 앞이 아니어도, -N도 인식. API 동기화(`ParseApiCard`)와 캐시를 읽을 때(`LoadOrInitializeCache`) 모두 적용하므로 다시 받지 않아도 된다.
- `KeywordDictionary.Analyze(card)`: 절 단위 지원 상태(✅ / ⛔ + 이유) — 지원률 리포트 · UI 표시용.

### 키워드 규칙 (엔진)
| 키워드 | 구현 |
| :--- | :--- |
| ≪속공≫ | 등장한 턴에도 어택 (ActionValidator · AI 어택 후보) |
| ≪돌진≫ | [어택 시] 효과 다음, 어택 대상을 가장 DP가 높은 액티브 상대 디지몬으로 바꿀 수 있다 (시큐리티 어택 → 디지몬 배틀). AI도 사용 |

| ≪방벽≫ | 배틀(시큐리티 배틀 포함)에서 소멸할 때 시큐리티 위 1장 파기로 막는다 → ≪길동무≫도 발동하지 않음 |

| ≪드로우≫ · ≪리커버리≫ · ≪퇴화≫ | 키워드 절의 동작 |
| ≪블로커≫ · ≪재밍≫ · ≪관통≫ · ≪길동무≫ · ≪재기동≫ · ≪시큐리티 어택≫ | 1단계 엔진 규칙에 키워드 사전만 연결 |

- **선택 인터페이스** `IChoiceProvider`: "~할 수 있다"(≪방벽≫ · ≪회피≫ · ≪돌진≫ · ≪연계≫)를 플레이어에게 묻는다. 엔진이 항상 추천 답을 함께 넘기고, AI · 테스트는 추천 답을 쓴다. WPF는 지금 예/아니요 창(`WpfChoiceProvider`) — 대상 고르기 팝업은 4단계.
- **시큐리티 디지몬의 [시큐리티] 효과**: 오픈되면 효과를 발휘한 뒤 배틀 (이전에는 디지몬 카드의 [시큐리티] 효과를 무시했다).

## 10. 3단계 결과 (문장 파서 1차)

### 구조 — `Engine/Effects/SentenceParser.cs` · `TargetSpec.cs`
키워드 사전이 읽지 못한 절은 문장 파서가 읽는다. **절 하나라도 읽지 못한 문장이 있으면 그 절 전체를 미지원으로 둔다** (일부만 조용히 처리하지 않음). `KeywordDictionary.Analyze`가 절마다 ✅ / ⛔ + 이유(읽지 못한 문장)를 돌려준다.

- **절** = `[시점 · 조건 표시]*` + 문장들. 문장마다 `Then,` · `If ~,`(조건) · `you may`(지금은 언제나 발휘) · `By ~,`(비용) · 동작을 읽는다.
- **시점**: 등장 시 · 진화 시 · 어택 시 · 소멸 시 · 메인(옵션) · 시큐리티 · 자신의 턴 개시 시 · 자신의 메인 페이즈 개시 시 · 자신의 / 상대의 턴 종료 시 · 어택 종료 시 · 이동 시, `[Your Turn]` / `[Opponent's Turn]` / `[All Turns]` · `[Once Per Turn]`
- **문장 안의 시점 "When ~,"**: 이 디지몬이 레스트 / 블록당함 / 배틀에서 이김 / 플레이어 · 디지몬을 어택, 상대 디지몬이 어택 / 소멸 / 레스트, 자신의 (다른) 디지몬이 등장 / 진화 / 어택 / 레스트 / 소멸 (특징 · 이름 조건 포함)
- **지속 효과**: `This Digimon gets +N DP`, `This Digimon gains ＜K＞ / ＜Security A. +N＞`, 테이머 `All of your Digimon get +N DP` — `While ~` 조건 포함 (조건부 키워드는 `CardInstance.ActiveKeywords`로 매번 다시 계산)
- **대상 구절** (`TargetSpec`): 수(N / all / up to N) · 쪽 · 액티브 / 레스트 · Lv · DP · 코스트 · 진화원 수 · 이름 / 특징 / 텍스트(`[A], [B] or [C]` 목록) · ＜키워드＞ 유무 · 가장 높은 / 낮은 DP · Lv · 진화원 수 · "이 디지몬 이하 DP" · `that Digimon`(앞 문장 대상)

## 11. 4단계 결과 (대상 선택 UI + "~할 수 있다" + AI 평가)

### 선택이 필요한 효과의 처리 흐름
효과가 무엇인가를 고르거나 "~할 수 있다"를 물어야 할 때, 엔진은 언제나 **AI 평가 함수의 추천 답**을 만든 뒤
효과 주인이 **플레이어이고 UI가 연결돼 있으면 플레이어에게 묻고**(`IChoiceProvider`), 아니면(AI · 테스트 · CLI) 추천 답을 그대로 쓴다.

| 선택 | 엔진 | 플레이어 (WPF) | AI · 테스트 |
| :--- | :--- | :--- | :--- |
| 효과 대상 (상대 / 자신의 디지몬 N마리, "up to N") | `ChooseTargets` — 내장 스크립트의 `PickEnemy` / `PickOwn`과 문장 파서의 대상 구절이 모두 여기를 지난다 | 카드 그림으로 고르는 창 (추천 ★), "up to"면 "고르지 않음" | 위협도 순 |
| "~할 수 있다" (`You may ~`) | 문장 단위 `Optional` → `AskYesNo` | 예 / 아니요 창 (추천 표시) | 문장 점수 ≥ 0이면 발휘 |
| 비용 (`By ~,`) | 낼 수 있을 때만 `AskYesNo` | 예 / 아니요 창 | 비용별 추천 (시큐리티 3장 이상 · 패 여유 · Lv.3 이하만 소멸 …) |
| 고르는 효과 (`Activate 1 of the effects below`) | `ChooseOption` | 선택지 버튼 창 (추천 ★) | 문장 점수 합이 가장 큰 선택지 |
| ≪돌진≫ · ≪연계≫ · ≪방벽≫ · ≪회피≫ | 2단계 그대로 | 예 / 아니요 · 고르기 창 | 키워드별 추천 |

- **묻지 않는 경우**: 후보가 고를 수 이하(고를 것이 없음), UI에서 옵션을 대상에 끌어다 놓아 이미 고른 경우(`ChosenTarget`), 어택 중인 디지몬 · 어택 대상이 조건에 맞는 경우(`preselected`).
- **AI 평가 함수** `Engine/Effects/AiEvaluator.cs`
  - `ThreatScore` / `Rank`: DP → Lv → ≪블로커≫ · 진화원 수 · 액티브 순 (같은 DP · Lv의 동률을 위협도로 가른다 — 이전에는 목록 순서)
  - `EstimateSentenceValue`: 효과 문장 하나의 이득 점수 (상대 제거 > 드로우 · 메모리 > 강화, 비용 · 자신에게 불리한 문장은 음수)
- WPF: `WpfChoiceProvider` — 확인 창, 카드 그림 고르기 창(MainWindow의 카드 그림 재사용), 선택지 창. 모두 추천 답을 표시한다.

## 13. 효과 지원 상태 표시 (UI를 엔진 실제 지원 상태에 맞춤)

이전까지 UI는 "내장 120장인가(IsEffectImplemented)"만 보고 API 카드를 모두 "⚠ 효과 미구현 / 키워드만"으로 표시했다.
이제 `Data/EffectSupport.cs`가 카드별 지원 상태를 계산하고, 도감 · 덱 빌더가 그것을 쓴다.

- 판정: API 카드는 `KeywordDictionary.Analyze`의 절 결과 → 전부 동작 / 일부 동작 N/M절 / 미지원 / 효과 없음.
  내장 카드는 카드별 스크립트가 있으므로 전부 동작, `StarterDecks.IsTextOnlyEffectCard` 목록(BT5-086)만 일부 동작.
  분석은 영어 원문(EffectText) 기준 — 한글 표시 문구(Display*)로 바꾸면 엔진과 어긋난다.
- 캐시: 카드 번호별 `ConcurrentDictionary`. 도감 전체(약 4,500장) 분석은 수 초라 앱 시작 · 도감 업데이트 때 백그라운드로 미리 계산하고,
  업데이트 뒤에는 `EffectSupport.ClearCache()`.
- UI: 바인더 배지("⚠ 일부 동작 3/5" · "⚠ 효과 미지원"), EFFECT 필터(전체 / 전부 동작 / 일부 동작 / 미지원),
  카드 상세(동작하지 않는 절과 이유, 최대 4절), 덱 추가 토스트(일부 · 미지원일 때만), 덱 빌더 지원률(전부 · 일부 · 미지원 장수, 덱 목록 ⚠),
  도감 검색 줄의 전체 지원률(효과 절 %).
- 정리: `CardData.HasUnimplementedBuiltInEffect` · `HasAutoKeywords` 삭제 (`IsEffectImplemented`는 "내장 카드" 뜻으로 유지).
- 테스트: `EffectSupportTests` 9개 (도감 전체 분석은 실제 cards_cache.json을 임시 폴더에 복사해서 연다).
- 남은 것: "동작하지 않는 절"은 영어 원문 절로 보여 준다 (한글 문구와 절 단위 대응이 없음 — 6단계 한글 생성 때 함께).

## 14. 6단계 결과 (한글 생성)

### 구조 — `Engine/Effects/KoreanEffectRenderer.cs`
영어 효과 문장을 **공식 한글판 표기**에 맞춘 한글 문장으로 만든다. 대전 판정은 계속 영어 문장(SentenceParser)으로 하고, 이것은 화면 표시용이다.
- 문장 틀은 SentenceParser와 같은 구조: 발동 시점 라벨 → 조건(If · While · When) → "~할 수 있다" → 비용(By ~ · ~ to ~) → 셈(for each) → 동작 → 기간.
- 동사는 네 가지로 활용한다: 평서("소멸시킨다") · "~할 수 있다" · 비용("~하는 것으로,") · 이어짐("~하고,"). 조건은 "~일 때," · "~인 동안," · 사건 뒤의 "~라면,".
- 조사(을/를 · 이/가 · 은/는 · 과/와 · 으로/로)는 앞말의 받침으로 고른다 (숫자 · 키워드 이름 기준 — 《관통》 (설명)을).
- 대상 구절은 꾸밈말을 앞으로: "1 of your opponent's Digimon with 4000 DP or less" → "DP 4000 이하인 상대의 디지몬 1마리".
- "it"은 절 안에 앞선 대상이 없으면 "이 디지몬", 있으면 "그 디지몬".
- 번역하지 못한 절은 영어 원문 앞에 `※(원문) `을 붙여 그대로 보여 준다(절을 하나도 번역하지 못하면 영어 원문 전체).

### 용어집 (공식 한글판에서 뽑음)
- 발동 시점: 【등장 시】 · 【진화 시】 · 【어택 시】 · 【소멸 시】 · 【자신의 턴】 · 【상대의 턴】 · 【서로의 턴】 · 【메인】 · 【시큐리티】 · [턴에 1회] …
- 키워드 이름과 설명: 공식 문구 4,000여 장에서 영어 ＜키워드＞와 한글 《키워드》가 함께 나온 효과 칸을 세어 가장 많이 쓰인 이름 · 설명문을 썼다 (《블로커》 · 《1 드로우》 · 《시큐리티 어택 +1》 · 《퇴화 1》 · 〈리커버리 +1 《덱》〉 · 《흡수진화 -2》 · 《디지버스트 2》 …).
- 카드 이름 · 특징: 공식 데이터(data/kr/cards_ko.json)가 있으면 영어 카드 캐시와 카드 번호로 맞춰 「아구몬」처럼 한글로, 없으면 영어 그대로.

### 화면 연결 — `KoreanCardData.DisplayEffectText` · `DisplayInheritedEffectText`
순서: ① 공식 한글(cards_ko.json) ② 내장 120장은 원래 문구(이미 한글판에서 옮긴 한글) ③ 생성한 한글 ④ 영어 원문. 생성 결과는 카드별로 캐시한다.

### 사용자 확인 대상
- **≪디코드≫와 DP 0 소멸**: Q&A에 직접 판정이 없다. "효과는 발휘하지만 소멸은 막지 못한다"로 구현 — 근거: 설명문 "배틀 이외", BT19-092 · BT19-002 판정(자신의 효과에도 유발), DP 0 소멸은 효과 처리 뒤 룰 처리.
- **배틀 에어리어 → 육성 에어리어 이동**(P-143 등): 에어리어를 떠나는 것으로 보지 않아 ≪오버플로우≫ · 떠날 때 효과를 처리하지 않고 링크 카드도 그대로 둔다 — 근거: Q&A "육성 에어리어에 이동할 때 ≪오버플로우≫는 처리되지 않습니다(에어리어에서 벗어나지 않았으므로)". 링크 카드를 남기는 것은 추정.
- **"If during an attack"**: 어택 선언부터 어택 종료(【어택 종료 시】 처리 전)까지로 판단.
- **디지크로스 재료가 배틀 에어리어의 디지몬일 때**: 그 디지몬 카드만 아래에 놓고 그 디지몬의 진화원 · 링크 카드는 트래시로 구현 (Q&A에 판정 없음).
- **디지크로스 재료를 놓는 순서**: 조건의 왼쪽 칸 카드가 위 (Q&A에 판정 없음).
- **DNA 진화에서 겹치는 순서**: 조건 왼쪽 칸 디지몬의 카드 묶음이 위, 오른쪽 칸 디지몬의 묶음이 아래로 구현. 등장한 턴 제한(어택)은 두 마리 중 먼저 나온 쪽을 따른다 (Q&A에 판정 없음).
