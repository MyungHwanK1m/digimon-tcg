# 🧩 카드 효과 확장 계획 — "수천 장의 카드가 실제로 동작하는 대전 엔진"

> 목표: 카드를 한 장씩 손으로 코딩하지 않고, **카드 데이터만 늘리면 효과가 동작하는 구조**로 바꾼다.
> 대상: 현재 도감 4,497장 (효과 구현 120장 · 나머지는 DP · 코스트 · 기본 키워드만 적용)

---

## 1. 현재 구조와 한계

| 영역 | 지금 | 문제 |
| :--- | :--- | :--- |
| 카드 데이터 | 내장 120장이 `StarterDecks.cs`에 C# 코드로 하드코딩, 나머지는 `cards_cache.json`(API 원본) | 카드 추가 · 수정 = 코드 수정 + 빌드. 내장 120장 중 약 40장은 번호와 실제 카드가 다름 |
| 효과 처리 | `GoldfishEngine`에 `if (CardId == "ST1-16")` 식 분기 약 25개 | 카드가 늘수록 분기가 끝없이 늘어남. 효과 문장과 실제 동작이 따로 놀음 |
| 플레이어 / AI | 플레이어는 `PlayCard`, `EvolveDigimon` 등, AI는 `ExecuteStage3AiTurn` 안의 별도 간소화 로직 | 같은 카드가 플레이어 · AI 쪽에서 다르게 동작. 효과를 두 번 구현해야 함 |
| DP · 버프 | `TamerDpBonus`, `TemporaryDpBonus`, `InheritedDpBonus` 같은 고정 필드 | 조건부 · 지속 효과("[자신의 턴] 진화원 4장 이상이면 +1000")를 표현할 수 없음 |
| 대상 선택 | 엔진이 임의로 첫 번째 / 최고 DP 대상을 고름 | "상대 디지몬 1체를 고른다" 같은 효과를 제대로 할 수 없음 |
| 한글 | 120장 수동 번역 | 4,000장 이상은 번역 불가능한 규모 |

## 2. 효과 문장 빈도 분석 (영어 효과가 있는 4,256장 기준)

**발동 시점** — [진화 시] 34.8% · [등장 시] 33.2% · [한 턴에 한 번] 33.7% · [자신의 턴] 26.1% · [시큐리티] 22.3% · [모든 턴] 21.2% · [공격 시] 19.7% · [메인] 16.4% · [소멸 시] 11.3%

**동작** — 트래시 34.0% · 소멸 19.1% · 메모리 +N 14.3% · DP +N 12.3% · 레스트 10.7% · 액티브 10.3% · 덱 위 N장 공개 9.9% · DP −N 6.1% · 패로 되돌리기 4.4%

**키워드** — ＜블로커＞ 11.9% · ＜드로우＞ 11.8% · ＜시큐리티 어택＞ 9.3% · ＜관통＞ 4.3% · ＜디지몬 퇴화＞ 4.1% · ＜재가동＞ 3.3% · ＜재밍＞ · ＜리커버리＞ · ＜속공＞ · ＜보복＞ · ＜습격＞ · ＜동맹＞ 각 2~3%

**특수 메커닉** (DNA 진화 · 디지크로스 · 앱 합체 · 링크 · ACE 오버플로 · 디지버스트) — 8.4%

→ 발동 시점 10종 + 동작 20종 정도 + 키워드 15종이면 **대부분의 효과 문장이 조합으로 표현된다.** 특수 메커닉은 후순위로 둔다.

## 3. 목표 구조

```
 [DigimonCard.io API] ──동기화──▶ cards_cache.json (영어 원본, 자동 갱신)
                                        │
 card_overrides.json (사람 관리) ───────┤  한글 이름 · 수동 수정 · 에라타
 effects/*.json      (사람/파서 생성) ──┤  카드별 효과 스크립트
                                        ▼
                         ┌──── 카드 효과 로더 ────┐
                         │ ① 수동 스크립트 (JSON)  │  우선순위 ① > ② > ③
                         │ ② 문장 템플릿 파서      │
                         │ ③ 키워드 사전           │
                         └──────────┬─────────────┘
                                    ▼  구조화된 Effect 목록 + 절별 지원 상태
                 ┌──────────── 규칙 엔진 (이벤트 기반) ────────────┐
                 │ 이벤트 버스 · 효과 대기열 · 지속 효과 레이어      │
                 │ 공용 행동 API (등장 / 진화 / 공격 / 시큐리티 …)   │
                 └───────┬───────────────────────────┬─────────────┘
                 플레이어 (UI 대상 선택)          AI (선택 정책만)
```

### 3-1. 데이터 분리
- `StarterDecks.cs`의 하드코딩 카드 정의를 없애고, 모든 카드를 `cards_cache.json`(API 원본) 하나에서 읽는다.
- 사람이 관리하는 정보는 `card_overrides.json`에 둔다: 한글 이름, 수동 수정값, 에라타.
- 추천 덱(프리셋)도 `decks/*.json`의 카드 번호 목록으로 옮긴다.
- 카드를 추가 · 수정할 때 빌드가 필요 없다.

### 3-2. 효과 모델 (Effect)
카드의 효과 한 절 = 아래 요소의 조합.

| 요소 | 예 |
| :--- | :--- |
| **출처** | 메인 효과 / 진화원 효과 / 시큐리티 효과 |
| **발동 시점** | 등장 시 · 진화 시 · 공격 시 · 소멸 시 · 자신의 턴 시작 / 종료 · 메인 · 시큐리티 · 상시(자신의 턴 / 상대 턴 / 모든 턴) |
| **조건** | "테이머가 있으면", "진화원 N장 이상", "메모리 N 이하", "상대 시큐리티 N장 이하" |
| **대상** | 소유자(자신 / 상대) · 위치(배틀 / 패 / 트래시 / 시큐리티) · 필터(Lv ≤ N, DP ≤ N, 색, 종류, 특징, 이름) · 수(1체 / 전부 / 최대 N) · 고르는 쪽 |
| **동작** | 드로우 · 메모리 ± · DP ± (기간) · 소멸 · 레스트 / 액티브 · 패 / 덱 아래로 · 시큐리티 트래시 / 추가(리커버리) · 퇴화 · 덱 위 N장 공개 후 추가 · 무료 등장 · 키워드 부여 |
| **제약** | 한 턴에 한 번 · "~할 수 있다"(선택) · 비용(레스트 등) |

예) `[When Digivolving] Delete 1 of your opponent's Digimon with 4000 DP or less.`
→ `{ 발동: 진화 시, 대상: 상대 · 배틀 · DP ≤ 4000 · 1체 · 자신이 선택, 동작: 소멸 }`

### 3-3. 효과 인식 파이프라인
1. **키워드 사전** — ＜블로커＞, ＜관통＞ 등 키워드는 규칙이 정해져 있으므로 이름만으로 동작을 붙인다.
2. **문장 템플릿 파서** — 영어 효과 문장을 정규식 / 문법 규칙으로 Effect 로 바꾼다. 빈도가 높은 문장 틀부터 추가한다. 해석하지 못한 절은 '미지원'으로 남긴다(조용히 무시하지 않는다).
3. **수동 스크립트(JSON)** — 파서가 못 읽는 카드는 `effects/{카드번호}.json`에 직접 적는다. 코드 수정 없이 데이터로 추가.
4. **C# 훅** — 정말 특수한 극소수 카드만.

카드마다 **절 단위 지원 상태**(✅ 동작 / 🟡 부분 / ⛔ 미지원)를 계산해 UI · 덱 빌더 · 리포트에 쓴다.

### 3-4. 규칙 엔진 (이벤트 기반)
- **공용 행동 API** — 등장 · 진화 · 공격 · 시큐리티 체크 · 소멸 · 턴 진행을 하나의 경로로. 플레이어와 AI가 같은 함수를 쓴다(지금의 `ExecuteStage3AiTurn` 별도 로직 폐기). AI는 "무엇을 할지"만 고르는 정책 계층이 된다.
- **이벤트 버스** — `CardPlayed`, `Digivolved`, `AttackDeclared`, `SecurityChecked`, `Deleted`, `TurnStarted`, `TurnEnded` 등을 발행하고, 해당 시점의 효과를 대기열에 올린다.
- **효과 대기열** — 공식 룰 순서(턴 플레이어 먼저, 동시에 발동한 효과의 처리 순서)대로 처리.
- **지속 효과 레이어** — DP · 키워드 · 시큐리티 어택 수치를 고정 필드 대신 "현재 유효한 효과들"로부터 계산한다. 조건부 효과가 자연스럽게 표현된다.
- **선택 인터페이스(`IChoiceProvider`)** — 대상 고르기 · "~할 수 있다" 여부를 묻는다. 플레이어는 UI 팝업으로, AI는 평가 함수로 답한다.
- 상대 턴 리플레이(`OpponentTurnEvents`)는 이벤트 버스에서 자동으로 만들어진다.

### 3-5. 한글화 — 번역하지 않고 "생성"한다
- 파싱된 Effect 를 한글 문장 틀로 렌더링한다. 예) `{진화 시, 상대 DP ≤ 4000 1체 소멸}` → "[진화 시] 상대의 DP 4000 이하 디지몬 1체를 소멸시킨다."
- 용어는 한 곳(용어집)에서 관리 → 4,000장 이상 표기가 자동으로 통일된다.
- 카드 설명에는 **한글(생성) + 영어 원문**을 함께 보여 준다. 해석하지 못한 절은 원문만 표시하고 ⛔ 표시.
- 공식 한국어판 표기를 확인할 수 있으면 용어집과 이름을 거기에 맞춘다.

### 3-6. 품질 관리
- 동작(액션) 단위 테스트, 파서 골든 테스트(영어 문장 → 기대 Effect), 인기 카드 시나리오 테스트.
- **지원률 리포트**: 세트별 · 전체 카드 기준 ✅ / 🟡 / ⛔ 비율을 앱(덱 빌더)과 테스트 출력으로 보여 준다. 단계마다 이 숫자로 진척을 잰다.

- 각 단계가 끝날 때마다 앱이 정상 동작하는 상태를 유지한다(중간에 게임이 깨지지 않게).

## 5. 정해야 할 것

1. **지원 범위** — 특수 메커닉(8.4%)을 언제 다룰지. 제안: 7단계까지 미루고, 해당 카드는 덱 빌더에서 '⛔ 미지원 메커닉'으로 표시.
2. **미지원 카드 정책** — 덱에 넣는 것을 막을지, 경고만 할지. 제안: 경고만(지금처럼), 대신 덱 지원률을 표시.
3. **한글 표기 기준** — 공식 한국어판 표기를 따를지, 자체 용어집으로 갈지. 제안: 공식 표기를 찾을 수 있으면 공식, 아니면 자체 용어집.

## 7. 0단계 결과 (현재 상태)

- **카드 데이터**: `StarterDecks.GetAllCatalogCards()` 120장을 생성 스크립트로 다시 만들었다. 이름 · 효과 문구는 공식 한글판 카드 이미지, 레벨 · 코스트 · DP · 진화 조건 · 등급은 DigimonCard.io 값. 오메가몬 3종의 2색 진화 조건은 카드 이미지로 확인(BT1-084 · BT5-086 레드/블루, BT3-112 레드/블랙).
- **효과 코드**: `GoldfishEngine.Effects.cs` (partial class)에 모았다. 기존 ID 분기 중 실제 카드와 달랐던 것(신태일 "최소 메모리 3", 슬래쉬엔젤몬 소멸, 해머 스파크 +2 등)은 실제 효과로 교체.
  - 키워드: 블로커 · 재밍 · 관통 · 길동무 · 재기동 · 리커버리 · 퇴화 · DP 마이너스(0이 되면 소멸)
  - 기간 효과: `GameState.TurnSequence`(플레이어 · 상대 턴마다 +1) 기준 "다음 상대의 턴 종료 시까지" 등
  - [자신의 턴] 진화원 DP는 주인의 턴에만 적용 (`CardInstance.IsOwnersTurn`)
  - [시큐리티] 옵션은 양쪽 공통 함수 하나(`ResolveSecurityOption`)로 처리

### 정한 것
- **같은 시점의 효과 순서**: 메인 효과 → 진화원 효과(아래에서 위). 공식 룰은 턴 플레이어가 순서를 고르지만, 대상 선택 UI(4단계) 전까지는 이 고정 순서를 쓴다.
- **같은 진화원 카드가 2장이면** 지금은 1번만 발휘한다 (이전 동작 유지). 공식 룰로는 장마다 발휘하므로 2단계에서 바꾼다.
